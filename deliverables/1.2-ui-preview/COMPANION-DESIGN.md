# 同频 PULSE 1.2：运动音乐与语音伴侣

本轮重做定位、UI和交互样机。用户已明确选择**必须离线**。当前交付为可独立安装的`1.2.0-preview`（包名`work.solour.pulse.preview`，不覆盖旧版）：音乐陪伴有代码接入；变化感知、离线中文回复识别、耳机收音与锁屏语音闭环仍待实现，界面会直接说明。对话演示是标注的脚本，不采集声音，也不代表识别准确率。

## 产品重心

面向喜欢运动的年轻人。核心价值是音乐跟随、适度陪伴和少量必要确认。用户不需要先选单车/跑步/器械，不需要设里程、组数、休息秒数，也不把这些估不准的数值做成主要成果。

成功指标改为：首次设置后能否一键开始、运动中需要点亮屏幕几次、询问是否打扰、耳机内回答是否被正确理解、拒绝和沉默是否被尊重。结束时不强迫用户看成绩单。

## 主流程（完整产品目标）

打开 → 首次一次性授权/设备设置 → 一键开始 → 手机收起 → 音乐持续 → 有足够变化证据时低频问一句 → 短回复/不回答 → 继续陪伴。

第一次的系统授权不能伪装成只需一次点击；日常开始不再重复这些设置。心率和可用运动信号不是启动音乐的门槛。数据缺失时维持普通音乐陪伴，不悄悄切换到模拟数据。

## 页面

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 首页 | 强烈视觉、耳机状态、一句开始文案 | 一个“开始音乐陪伴”；偏好放右上角 |
| 陪伴中 | 波形、当前音乐状态、一句反馈 | 一个暂停按钮；结束为次要入口 |
| 询问/等待回答 | 同一陪伴界面显示问题和听取状态 | 完整版不出现手动确认/删除按钮 |
| 偏好 | 音乐、离线语音、设备、隐私 | 低频设置，不阻断开始 |
| 结束 | 简短告别 | 不展示里程、组数和训练成绩 |

视觉使用炭黑`#151218`、燃橙`#FF6638`、玫红`#FF3C81`及少量电紫`#8064FF`。主要按钮燃橙配深色字，减少按钮数量，靠字号和留白建立层级，不沿用素雅健身记录本的气质。

## “问一句、答一句”的设计

| 可能发生的变化 | 询问示例 | 肯定回复 | 否定/不明确/沉默 |
| --- | --- | --- | --- |
| 疑似恢复 | “现在在休息吗？” | 放轻音乐，保留已确认上下文 | 不认定休息，不改变原状态 |
| 活动节奏变化 | “运动节奏好像变了，要换个更带劲的节奏吗？” | 换音乐节奏 | 不把变化认定为某种器械或运动 |
| 疑似准备结束 | “要结束这次陪伴吗？” | 明确确认后结束 | 不自动结束 |
| 用户说“安静陪我” | 简短应答后保持安静 | 本次不再询问 | 音乐继续 |

当前策略原型：至少两个独立信号类别、变化持续20秒、数据新鲜才允许提出候选问题；问题播完后才开启6秒回复窗口；普通询问至少隔5分钟，拒绝或沉默后至少10分钟不再追问；“不是”不能被误匹配成“是”；未知回复不当作同意。以上参数用于交互原型，不是经过实机校准的运动分类算法。

实际数据接入时，不能把同一个心率的两个派生指标当成两个独立来源。心率加速、下降、手机不动，都不能单独证明跑步、休息或结束。推测只触发询问，用户的简短回答才决定是否采用变化。

## 数据的真实边界

- 标准BLE心率可用时，只作为节奏参考与变化线索，不从心率反推速度、里程或运动项目。
- 手机步数与加速度只有在手机随身、权限和传感器更新正常时才有意义。手机在单车支架、储物柜或包里不动，不等于人没动。无更新也不等于步数为零。
- 手环的步数/活动数据是否开放取决于厂商接口；不能因品牌是华为或小米就宣称拿得到。标准RSC/CSC、手机运动数据与厂商私有数据应分别处理。
- 没有足够信号，优先安静陪伴，少问；不能为了展示“智能”而随机问“你是不是休息了”。
- 本体验稿尚未接入手机步数或运动状态识别；演示中的候选变化均为脚本输入。

## 完全离线的技术路线

完整产品采用随包提供的端侧中文识别组件和有限指令词表，首先打通“对/不是/继续/休息/安静陪我/结束”。不以系统`EXTRA_PREFER_OFFLINE`提示当作完全离线保证，也不启用联网识别兜底。系统离线中文TTS用于播放问题，与语音识别是两项独立能力。

状态链：变化候选 → 播完问题 → 压低音乐/短时收音 → 本地识别 → 校验问题ID和回复可信度 → 应用已确认意图/维持原状 → 关闭收音并恢复音乐。原始录音不默认保存、不上传。这个体验稿没有麦克风和网络权限，所以不会实际收音。

耳机已连接只证明能输出音频，不能证明已经能用耳机麦克风。完整版本必须验证有线耳机、经典蓝牙切换A2DP/HFP、BLE Audio、风噪、跑步喘气、来电和系统助手抢占。来电、断连或焦点被抢占时取消待确认问题和收音，旧问题的迟到结果不能作用到新问题。

本轮不设计常驻唤醒词，不承诺任何时候说话都能被听见。标准耳机媒体键可作为播放/暂停的补充；不能把双击或长按当作所有耳机通用的App语音键。“全程不掏手机”最终必须按具体手机与耳机组合实测。

## 当前体验稿的完成范围

已接入：新的默认入口和热烈配色、一键音乐陪伴、三档离线原创循环、可选标准BLE心率参考、标准媒体控制回调、结束不新建训练成绩、音频被占用时明确显示并支持重试、离线TTS可用时的演示播报、清楚标注的对话脚本、策略原型与框架测试。

未实现：真实运动变化感知、手机步数接入、中文回复识别、真实麦克风收音、锁屏问答闭环、常驻唤醒词。耳机按键与播放效果尚未真机验证。完整语音功能交付前，应先完成一组手机+耳机的端到端验证，再扩展适配矩阵。

## 下一阶段验收重点

1. 不选项目、不设数字目标，首次设置后能一键开始；运动中没有必须点屏幕的确认动作。
2. 每次提问必须有新鲜证据和冷却时间；误判被否定后不反复追问；没有回复不误切换或误结束。
3. 语音问题播完再开收音；低可信回复不执行；“不是”与“是”分开；旧问题结果不能越界。
4. 锁屏、音乐压低/恢复、蓝牙麦克风切换、来电中断和耳机断连均用真实设备验证。
5. 无设备、无数据、无离线语音能力时清楚说明并降级，不伪装成已完成的智能陪伴。
